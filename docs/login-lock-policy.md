# 로그인 실패와 계정 잠금

## 정책

- 같은 계정에서 비밀번호를 5회 연속 잘못 입력하면 로그인을 잠근다.
- 잠긴 계정은 올바른 비밀번호를 입력해도 로그인할 수 없다.
- 잠금은 시간 경과로 해제되지 않는다. 일반 회원은 비밀번호 찾기를 통한 재설정 완료로 해제한다.
- 관리자 계정은 사용자 로그인과 공개 아이디·비밀번호 찾기 및 재설정을 사용할 수 없다. 관리자 로그인은 `/api/v1/admin/login`을 사용하며, 관리자 잠금 해제는 별도 운영 절차로 처리한다.
- 잠기기 전에 정상 인증하면 연속 실패 횟수를 0으로 초기화한다.
- 존재하지 않는 계정에는 잠금 행을 생성하지 않는다.
- 계정 차단과 탈퇴 상태는 별도 정책이며 비밀번호 재설정으로 해제되지 않는다.
- IP 기준 요청 제한은 이 정책에 포함하지 않는다.

## 저장과 동시 요청

AUTH DB의 `user_login_locks`에서 계정별 실패 횟수와 잠금 시각을 관리한다. `auth_id`는 계정당 한 행만 존재하도록 고유 제약을 가진다.

로그인 비밀번호 검증은 AUTH 계정 행을 먼저 비관적 락으로 조회하고 잠금 행을 조회 또는 생성한다. 잠금 행이 없는 최초 요청도 같은 계정에 대해서는 순서대로 처리한다.

`LoginAttemptService`는 별도 트랜잭션에서 검증한다. 비밀번호 불일치와 로그인 잠금 예외는 실패 기록을 커밋한 뒤 전달한다. DB 오류 등 다른 예외는 정상적으로 롤백한다.

로그인 메서드는 바깥 트랜잭션을 유지하지 않는다. 동시 로그인 요청이 별도 검증 트랜잭션을 기다리면서 DB 연결을 추가 점유하는 것을 방지한다.

## 비밀번호 재설정

USER 서비스의 비밀번호 찾기 재설정 완료 이벤트에는 `passwordReset=true`를 포함한다. AUTH는 계정 행을 잠근 상태에서 비밀번호 갱신과 로그인 잠금 해제를 같은 트랜잭션으로 처리한다. 일반 사용자 수정 또는 일반 비밀번호 변경 이벤트는 잠금을 해제하지 않는다.

Kafka 이벤트가 AUTH에 반영된 뒤 새 비밀번호로 로그인할 수 있다. 동일한 재설정 이벤트가 다시 전달되어 비밀번호가 이미 같다면 실패 횟수와 잠금을 다시 초기화하지 않는다.

## 테이블 생성

`auth-service/src/main/resources/sql/schema.sql`에 `user_login_locks` 생성문을 포함한다. 기존 DB에 테이블만 추가할 때는 해당 `CREATE TABLE user_login_locks` 구문을 실행한다. `schema.sql` 전체 실행은 기존 테이블을 삭제하므로 초기 구성 시에만 사용한다.

USER와 AUTH가 같은 이벤트 필드를 처리하도록 함께 배포한다.

## 응답

5회째 실패 또는 잠긴 계정의 로그인 요청은 HTTP `403`, 코드 `USER_LOGIN_LOCKED`와 비밀번호 찾기 안내를 반환한다. 기존 사용자 로그인 화면은 서버 오류 메시지를 표시한다.
