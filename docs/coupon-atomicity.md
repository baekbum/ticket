# 쿠폰 사용의 원자성

최종 예매 생성에서 사용자 보유 쿠폰인 `UserCoupon` 행을 `PESSIMISTIC_WRITE`로 조회한다. 잠금을 획득한 뒤 소유자, ISSUED 상태, 쿠폰 정책과 유효 기간, 최소 주문 금액을 검증하고 USED로 변경한다. 쿠폰 사용, 예매·티켓·할인 내역 저장은 기존 예매 트랜잭션에서 함께 커밋·롤백하며 별도 트랜잭션을 만들지 않는다.

같은 쿠폰을 사용하는 뒤 요청은 먼저 처리 중인 요청의 종료를 기다린다. 앞 요청이 커밋하면 USED 상태를 확인하고 거부하며, 롤백하면 ISSUED 상태를 확인해 진행할 수 있다. 서로 다른 공연의 예매에도 같은 쿠폰 행 잠금이 적용되므로 공연별 구매 매수 잠금에 의존하지 않는다.

`selectByIdForUpdate()`는 잠금 조회 후 `refresh(..., PESSIMISTIC_WRITE)`로 영속성 컨텍스트의 이전 상태도 갱신한다. 관리자 사용자 쿠폰 수정에도 같은 조회를 사용한다. 취소·결제 만료·환불 복구에서 연관관계로 읽은 쿠폰은 `lockForUpdate()`로 잠금과 갱신을 수행한 후 USED 여부를 확인한다. 복구 시 만료 여부는 잠금 획득 후의 시간으로 판단한다. 두 잠금 메서드는 MANDATORY이므로 호출자의 트랜잭션 안에서만 실행된다.

화면에서 호출하는 쿠폰 사용 가능 여부 확인은 일반 조회를 유지한다. 사전 조회 결과가 최종 사용을 보장하지 않으며 실제 예매에서 다시 검증한다. 만료 스케줄러의 조건부 UPDATE도 DB 행 잠금을 따르므로, 동시에 사용 처리한 행은 잠금 해제 후 ISSUED 조건을 다시 확인한다.

새 컬럼이나 테이블은 추가하지 않는다. 기존 쿠폰 발급과 할인·복구 정책은 변경하지 않는다.

## 검증

`UserCouponConcurrencyIntegrationTest`는 실제 트랜잭션과 별도 스레드로 다른 공연의 동시 사용, 앞 요청의 커밋·롤백, 오래된 영속성 컨텍스트, flush 이후 실패 시 예매·쿠폰·좌석·매수·할인 내역 롤백, 관리자 취소 상태 보존, 만료 UPDATE와 사용 처리의 경합을 검증한다.

기본 실행은 H2 PostgreSQL 모드다. `TICKET_COUPON_TEST_POSTGRES_PORT`를 설정하면 해당 포트의 전용 DB `ticket_coupon_atomicity_test`에 계정 `ticket_test`로 연결한다. 이 테스트는 create-drop으로 테이블을 생성·삭제하므로 개발 DB 대신 임시 PostgreSQL 인스턴스에서 실행한다.

2026-10-22 검증 결과:

- H2에서 쿠폰·예매·환불 관련 테스트 128개 통과.
- 티켓 서비스 전체 테스트 563개 통과. 실패·오류·건너뛰기 0개.
- 전체 실행에서 쿠폰 동시성 테스트 6개는 임시 PostgreSQL 17.5, Redis 테스트 15개는 실제 로컬 Redis의 DB 15를 사용했다.
- 검증 후 임시 PostgreSQL 컨테이너를 제거했다. 개발 DB 스키마 변경은 필요하지 않다.
