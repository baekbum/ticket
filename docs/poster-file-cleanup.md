# 포스터 파일 정리

공연 등록·포스터 교체는 기존 공연 트랜잭션 안에서 `EventPosterService.saveForTransaction`을 호출한다. `MANDATORY`로 트랜잭션 없는 파일 저장을 거부하고, 저장 직후 트랜잭션 후처리를 등록한다.

- 커밋: 새 포스터를 보존하고 기존 포스터를 삭제한다.
- 롤백: 기존 포스터를 보존하고 이번에 저장한 새 포스터를 삭제한다.
- 결과 불명: DB가 커밋됐을 가능성이 있으므로 새 포스터를 보존한다.

다회차 등록 중 후속 일정에서 실패하거나 DB 커밋이 실패해도 같은 롤백 후처리가 적용된다. 파일 저장 도중 오류가 발생하면 아직 후처리를 등록하지 않았으므로 `FileStorageService`가 자신이 만든 부분 파일을 즉시 정리한다. 같은 이름으로 이미 존재하던 파일은 삭제하지 않는다.

삭제 실패는 완료 구분·파일 URL·오류 유형을 로그로 남긴다. 커밋된 공연 변경을 실패 응답으로 바꾸거나 원래 롤백 원인을 덮어쓰지 않는다. 외부 URL과 업로드 루트 밖의 파일은 기존 파일 저장소의 검증에 따라 삭제하지 않는다.

이 처리는 트랜잭션 콜백을 사용한다. 강제 종료로 콜백을 실행하지 못하거나 파일 삭제가 실패하면 미사용 파일이 남을 수 있으며, 자동 재시도 작업은 저장하지 않는다. 파일 정리 실패 로그와 미사용 파일에 대한 별도 운영 정리가 필요하다.

`EventPosterTransactionIntegrationTest`는 실제 DB 트랜잭션과 임시 업로드 디렉터리로 커밋 전 파일 보존, 롤백·커밋 실패 정리, 다회차 등록 실패, 삭제 오류의 영향을 검증한다. `FileStorageServiceTest`는 업로드 실패 시 부분 파일 정리와 기존 파일 보존을 검증한다.
