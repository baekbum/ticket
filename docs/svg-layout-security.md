# SVG 좌석 배치도 정제

관리자 업로드에서 정제한 SVG만 저장한다. 기존 저장본도 일반 사용자·관리자 조회 응답에서 같은 정제를 거친다. 잘못된 기존 문서는 원문 대신 빈 SVG 문자열을 반환하며, 사용자 화면은 기존 구역 목록 표시로 대체한다. DB 원문을 일괄 수정할 필요는 없다.

서버는 외부 엔티티와 DOCTYPE을 차단한 XML 파서로 문서를 읽고, 허용한 SVG 요소·속성으로 새 문서를 만든다. `script`, 이벤트 속성, `foreignObject`, 링크, 이미지, `use`, 애니메이션, 외부 네임스페이스 및 원본 스타일시트는 복사하지 않는다. 색상·좌표·텍스트·구역 메타데이터와 내부 그라데이션·클리핑 참조만 지원한다. `fill`, `stroke`, `clip-path`의 URL은 `url(#id)` 형태의 로컬 참조만 허용한다.

단순한 인라인 색상·선·폰트 스타일과 `<style>`의 단순 클래스(`.label`), ID(`#stage`), 요소(`text`) 선택자는 허용한 표시 속성으로 변환한다. 선택자를 쉼표로 나열할 수 있으며 ID > 클래스 > 요소 우선순위와 같은 우선순위의 선언 순서를 적용한다. 인라인 선언은 마지막에 적용한다. 단순한 `font` 축약형은 `font-style`, `font-weight`, `font-size`, `font-family`로 풀어 저장한다. 글자색·배경색과 `pointer-events: none`이 유지되어 구역 라벨이 보이고 클릭을 가로채지 않는다. 원본 `<style>`과 `style` 속성은 최종 SVG에 남기지 않는다.

복합 선택자, CSS 이스케이프, 조건부 규칙, `!important`, 외부 이미지, 필터 및 복잡한 폰트 선언은 지원하지 않는다. 이런 기능에 의존한 배치도는 표시가 달라질 수 있으므로 단순 표시 속성을 사용해 다시 업로드한다. 스타일 규칙은 문서당 최대 256개로 제한한다. 좌석 구역의 `id`, `class`, `data-layout-key`, `data-area-name`, `data-grade`, `data-price`는 유지된다. 기존 DB에 원본 CSS가 남아 있는 배치도는 조회 시 새 정제를 적용하므로 재업로드할 필요가 없다. 이전 정제 과정에서 이미 저장본의 스타일이 제거된 경우에는 원본 파일을 다시 업로드해야 한다.

브라우저에서도 DOMPurify와 명시적 SVG 허용 목록으로 정제한다. 텍스트 노드(`#text`)를 명시적으로 허용해 구역 번호, 무대 이름과 선택 안내 텍스트를 유지한다. 허용하지 않은 요소는 내부 내용까지 제거한다. 구역 선택 속성을 붙이기 전과 `dangerouslySetInnerHTML`에 전달하기 전에 적용하며, 도형의 `data-area-id`, 키보드 선택 및 접근성 속성을 유지한다.

검증에는 서버 정제 단위 테스트, 악성 업로드 저장·기존 DB 조회 서비스 테스트, 브라우저 DOM 삽입 후 이벤트 실행 차단 테스트를 포함한다. XML 외부 엔티티, 외부 URL, 네임스페이스 혼합, CDATA, 스크립트, 이벤트 속성 및 애니메이션을 검사한다.
