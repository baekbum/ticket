# SVG 좌석 배치도 정제

관리자 업로드에서 정제한 SVG만 저장한다. 기존 저장본도 일반 사용자·관리자 조회 응답에서 같은 정제를 거친다. 잘못된 기존 문서는 원문 대신 빈 SVG 문자열을 반환하며, 사용자 화면은 기존 구역 목록 표시로 대체한다. DB 원문을 일괄 수정할 필요는 없다.

서버는 외부 엔티티와 DOCTYPE을 차단한 XML 파서로 문서를 읽고, 허용한 SVG 요소·속성으로 새 문서를 만든다. `script`, 이벤트 속성, `foreignObject`, 링크, 이미지, `use`, 애니메이션, 외부 네임스페이스 및 스타일시트는 복사하지 않는다. 색상·좌표·텍스트·구역 메타데이터와 내부 그라데이션·클리핑 참조만 지원한다. `fill`, `stroke`, `clip-path`의 URL은 `url(#id)` 형태의 로컬 참조만 허용한다.

단순한 인라인 색상·선·폰트 스타일은 허용한 표시 속성으로 변환한다. `<style>`의 CSS 규칙이나 외부 이미지에 의존한 SVG는 표시가 달라질 수 있다. 해당 배치도는 도형에 `fill`, `stroke` 등의 표시 속성을 지정해 다시 업로드해야 한다. 좌석 구역의 `id`, `class`, `data-layout-key`, `data-area-name`, `data-grade`, `data-price`는 유지된다.

브라우저에서도 DOMPurify와 명시적 SVG 허용 목록으로 정제한다. 구역 선택 속성을 붙이기 전과 `dangerouslySetInnerHTML`에 전달하기 전에 적용하며, 도형의 `data-area-id`, 키보드 선택 및 접근성 속성을 유지한다.

검증에는 서버 정제 단위 테스트, 악성 업로드 저장·기존 DB 조회 서비스 테스트, 브라우저 DOM 삽입 후 이벤트 실행 차단 테스트를 포함한다. XML 외부 엔티티, 외부 URL, 네임스페이스 혼합, CDATA, 스크립트, 이벤트 속성 및 애니메이션을 검사한다.
